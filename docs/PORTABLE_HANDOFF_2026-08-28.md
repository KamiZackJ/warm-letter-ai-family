## 2. 七分钟展示顺序

1. 打开交付包根目录的 PDF，用 2 分钟讲产品问题、AI 价值、真实材料接入和当前边界。
2. 双击 [`../interactive/index.html`](../interactive/index.html)，确认页面顶部显示“受控真实素材 / 固定审核稿 / 非实时 OpenAI 调用”。
3. 查看照片裁切图并播放原始 m4a；切换 A/B/C，说明三版只改变表达，不改变已核对事实。
4. 编辑一段正文，展示来源变为待核对；完成确认后进入阅读端并提交一条本地回复。
5. 打开 [`../interactive/PROJECT_INTEGRATION.md`](../interactive/PROJECT_INTEGRATION.md)，区分“队友提供的内容成果”和“本项目完成的产品、隐私、证据与交接能力”。
6. 打开 [`../adapter/README.md`](../adapter/README.md)，说明本阶段还交付了可复用的 `confirmedDraft` 长图适配器，而不只是重新整理素材。

## 6. 推荐推进顺序

1. 先完成真实 OpenAI 四素材受控 E2E，验证 AI 核心价值和事实不漂移。
2. 再完成微信双设备端到端，把本地演示升级为真实分享、播放和回复证据。
3. 决定生产存储、审核、删除和部署架构，再开放 3+3 真人测试。
4. 将已验证的 `confirmedDraft` 长图适配器接入 API 任务，之后复用同一确认版本扩展短片。

每次阶段更新必须同时写明：完成事实、证据位置、未完成边界、风险变化和下一步前三项。任何阻塞超过 4 个工作小时，应由项目经理拆出可并行任务或升级外部依赖。
