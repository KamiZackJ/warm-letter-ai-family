# 暖笺外部验收与参赛取证手册

更新时间：2026-08-16（Asia/Shanghai）

本手册用于关闭真实 AI、微信双设备和参赛提交门禁。模板、mock、合成 Demo、本地单元测试和单设备录屏只能用于准备，不得替代本手册要求的外部证据。

## 1. 证据目录与安全边界

每次正式取证使用独立目录：

```text
docs/evidence/YYYY-MM-DD/<gate>-<run-id>/
```

仓库只提交脱敏记录、哈希、截图和结论。原始授权文件、身份证明、OpenAI 密钥、微信 AppSecret、登录令牌、openid、完整签名 URL、未脱敏家庭内容和报名敏感信息只保存在团队受控位置；临时处理文件统一放在 `D:\tmp\warm-letter-ai-family`。

每个证据包必须包含：

- `README.md`：目标、提交 SHA、环境、执行人、复核人、时间、结论和未通过项。
- `commands.md`：实际命令、退出码和脱敏关键输出。
- `artifacts.sha256`：提交文件及外部录像/母版的 SHA-256。
- `issues.md`：失败步骤、返修单 ID、重测结果和残余风险。

执行人和复核人不得为同一人。证据缺版本、步骤或原始结果时，项目经理按未通过处理。

## 2. W1 真实 AI 四素材闭环

### 2.1 前置条件

- 团队批准的 OpenAI 项目凭据、目标模型、额度和网络可用。
- 1 张授权生活照片、1 张授权聊天截图、1 段授权中文语音、1 段文字近况。
- 人工事实基准：逐条记录照片细节、截图文字、语音原句、文字事实、禁止推断项和允许的情感表达。
- 所有素材记录 SHA-256、所有者、授权范围和是否允许进入公开视频/PDF。

### 2.2 必录流程

1. 从空账号或清空后的测试账号开始，显示当前提交 SHA 和 `competition` 环境标识。
2. 逐项上传四类素材，记录素材 ID、MIME、大小、哈希和上传完成状态。
3. 选择收信人、语气、篇幅、重点和禁用内容；确认未选择素材不会进入请求。
4. 发起真实生成，记录脱敏 request ID、模型、usage、耗时、任务状态与重试次数。
5. 保存通过共享 schema 校验的结构化草稿；逐段列出 `sourceRefs`。
6. 将草稿与人工事实表逐项对照，标记正确、遗漏、夸大、无依据和错误来源。
7. 演示一次用户改写、来源复核和最终确认；确认后正文不得被后台生成漂移。
8. 分别执行供应商超时、非法结构、非法来源引用和一次可恢复重试。
9. 删除或取消选择一项素材，证明后续请求不再发送该素材。
10. 由非执行人复核脱敏、事实一致性和对外表述后签字。

### 2.3 退出条件

- 四类素材均被真实供应商处理，并能在草稿中核对对应事实和素材 ID。
- 严重事实编造为 0；任何无法人工确认的内容不得作为事实发布。
- 凭据只来自环境变量，日志和证据中没有密钥、原始令牌、完整素材或完整提示词。
- 成功、失败、超时、格式错误、非法引用、重试和未选素材负向场景均有证据。

## 3. W3 微信双设备闭环

### 3.1 前置条件

- 团队控制的微信 AppID、AppSecret、开发者和体验成员。
- 服务端正式 `code2Session`，可达且证书有效的 HTTPS API，不使用 `touristappid`、回环地址或 Demo 回退。
- 设备 A 为寄信端，设备 B 为全新或已清空本地存储的收信端；记录系统、微信版本、网络和设备型号。

### 3.2 必录流程

1. 开发者工具显示编译模式、AppID、环境标识和请求域名；五页均保留非 Demo 标识。
2. 设备 A 登录并实际上传照片、截图和语音，完成预览、播放、删除和重新上传。
3. 设备 A 使用真实 AI 生成、编辑、确认并签发短期分享。
4. 设备 B 未登录打开分享，读取同一确认版本、来源、图片和原始语音。
5. 设备 B 提交回复并用同一 token 刷新；设备 A 回查相同回复。
6. 重签后验证旧 reader、旧媒体和旧回复请求失效，新链接正常且保留合法历史回复。
7. 验证错误 token、过期 token、撤销、API 断网、媒体失败、重新连接和持久错误状态。
8. 删除素材或家书后验证分享立即失效、在线对象不可读，并记录后续删除任务状态。

### 3.3 退出条件

- 开发者工具和两台真实设备均有连续录像，关键请求具有脱敏时间线。
- 两端正文、来源、媒体和回复一致；设备 B 不调用寄信人私有接口。
- 错误、过期、撤销和删除场景返回预期安全状态，不泄露对象键、openid 或令牌。
- 真机大字号、读屏、焦点/按压反馈和不小于 44 px 的主要触控区由项目经理复验。

## 4. 比赛视频、PDF 与提交冻结

### 4.1 100-140 秒视频母版

| 时间 | 画面证据 | 对应评分 |
| --- | --- | --- |
| 0-15 秒 | 异地家庭真实沟通痛点，避免制造亲情焦虑 | 场景真实性 |
| 15-40 秒 | 主动选择照片、截图、语音、文字及隐私边界 | 创新性、可信度 |
| 40-75 秒 | 真实 AI 任务、来源引用、失败恢复、用户编辑确认 | AI 核心价值 |
| 75-105 秒 | 长辈大字阅读、原始语音、回复与寄信端回查 | 完成度 |
| 105-125 秒 | 同一确认版本的长图/短片或明确标注的路线图 | 完成度、孵化潜力 |
| 125-140 秒 | 用户反馈、体验入口、AI 工具来源和双话题 | 孵化潜力、合规 |

未实现能力只能以“下一步”出现，不得通过后期画面伪装为已运行功能。发布前核对 30 秒至 3 分钟时长、公开可见、清晰字幕/声音、`#AI未来挑战赛`、`#AI产品实现` 和“含 AI 生成内容”声明。

### 4.2 PDF 最小结构

1. 产品概述与一句话价值。
2. 目标用户、使用场景和已验证/待验证假设。
3. 核心闭环与来源追溯、用户确认、隐私边界。
4. 真实 AI 的不可替代作用和失败恢复。
5. 技术架构、当前实现、测试与安全证据。
6. 长辈体验、用户观察结果和返修改进。
7. 孵化路线、成本、渠道、留存与合规计划。
8. Demo、代码、视频、授权和 AIGC 工具来源。

PDF 必须逐页渲染检查中文、溢出、图片清晰度、二维码和链接，并记录最终文件 SHA-256。

### 4.3 提交与冻结

- 两名成员交叉检查作品名、团队名、快手昵称/ID、视频链接、PDF、Demo、代码 SHA 和报名字段。
- 归档发布前预览、公开视频无痕访问、报名成功回执、所有最终文件哈希和发布时间。
- 提交后冻结公开作品与对应版本；后续研发使用新分支，不覆盖、隐藏或修改已提交内容。

## 5. 放行签字

项目经理只接受以下结论：`通过`、`返修后通过`、`未通过`。W1、W3、比赛材料分别签字，不允许用一个局部成功推导其他门禁完成；W1 与 W3 未通过时不得放行 G2，全部 P0/P1、视频、PDF、Demo 和版本一致性未通过时不得放行 G3。
