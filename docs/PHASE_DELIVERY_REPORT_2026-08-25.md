## 3. 代码成果

### 3.1 创作端：微信小程序

- 素材选择、会话恢复、照片/截图/语音/文字入口。
- 生成任务轮询、幂等键、丢响应恢复和失败状态。
- 草稿标题、称呼、正文和结尾编辑。
- 段落级来源归因：`ai`、`needs-review`、`sources-confirmed`、`user-supplied`。
- 修改段落后清除旧来源并要求重新核对，防止用户改写仍伪装成 AI 事实。
- 阅读端大字/特大字、来源展开、图片/音频重试、回复失败重试。

### 3.2 服务端：Fastify API

- 用户、素材、家书、生成任务和回复的状态机。
- `presign -> upload -> complete` 媒体上传链路，类型、扩展名、大小、魔数和 owner 校验。
- 分享令牌只保存 hash，支持短期过期、重签和撤销。
- 公开 reader DTO 与寄信人私有接口分离；媒体使用独立短期签名凭据。
- 公开阅读、媒体读取和匿名回复具备统一错误矩阵、限流、内容安全兜底和回复上限。
- OpenAI 适配器已经存在，能处理图片、截图、音频和结构化输出；真实凭据与真实四素材事实证据仍未完成。

### 3.3 收信端：H5

- 已确认版本阅读、来源展开、图片、原始音频和系统朗读。
- 三档阅读字号、移动端大字正文、跳转正文、回复幂等和失败恢复。
- 已有真实浏览器矩阵证据，但 H5 仍是公开阅读端，不负责创建或修改家书。

## 4. 第二部分真实素材成果

第二部分材料位于微信文件目录，当前不复制原始照片和语音到 Git 仓库。标准成果包的核心文件为：

- `README.md`：成果包入口和打开顺序。
- `与第一位同学融合说明.md`：整体功能与内容模块的接入边界。
- `素材/生活照片_商店货架.jpg`：只提取货架、商品和价签；不识别右侧路人。
- `素材/语音_暖笺_1.m4a`：约 8.895 秒；安全语义为“上午开会有点累，中午外卖附送饮品，感觉开心”。
- `成品/三版温柔家书.txt`：短笺、日常、留白三版。
- `展示/暖笺_真实素材家书展示.html`：离线展示照片、原音、三版家书、事实映射和验收结果。
- `测试/暖笺_真人用户测试工具.html`：匿名评分并下载 CSV。
- `接口/`：固定案例输入/输出、输入 Schema、安全生成提示词。
- `规则/content_safety_policy.json`：身份、语言、事实和隐私边界。
- `核验/`：隐私核验、7 条自动验收和素材 manifest。
- `配套文件/暖笺_第二部分_实际成果册.docx`：成果汇报册。
- `配套文件/暖笺_用户测试与问题记录.xlsx`：真人测试、问题闭环和自动汇总。

### 4.1 内容侧已完成事实

- 事实边界已经降级处理：不清晰的饮品名称统一写为“饮品”。
- 照片中的路人不被识别、描述或写入家书。
- 商品和价签只作为画面事实，不推导购买、食用、口味或健康功效。
- 收信人关系未指定时使用中性称呼“家里人”，不猜测“爸爸/妈妈”。

## 6. 当前明确缺口

1. **FIX-021 署名快照**：署名仍未进入服务端确认快照；小程序本地默认署名不能作为跨设备事实。
2. **M4 长图与短片**：`render_long_image`、`render_video` 只有契约预留，没有渲染器、任务 API 或成品证据。
3. **真实 AI 证据**：尚无照片、截图、中文语音和文字一起经过真实供应商并完成事实核对的脱敏录像。
4. **微信双设备**：正式 AppID、HTTPS API、登录、另一设备读信/回复和真机适老验证未完成。
5. **生产边界**：PostgreSQL、S3/OSS、独立队列、正式内容审核、跨实例限流、完整删除 SLA 和监控未完成。
6. **真人测试**：6 名真实参与者的反馈、问题复测和通过结论尚未产生。
7. **教程文件命名**：清单中提到的“完整使用与融合教程.docx”当前不存在，包内实际文件是“实际成果册.docx”。
