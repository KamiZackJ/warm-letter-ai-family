## 4. 接手后的首日操作

本仓库固定使用 Node.js `22.23.2`（见 `.node-version`）和 pnpm `11.19.0`。在仓库根目录执行：

```powershell
$env:TEMP = 'D:\tmp\warm-letter-ai-family'
$env:TMP = $env:TEMP
New-Item -ItemType Directory -Force $env:TEMP | Out-Null
node --version
pnpm --version
pnpm install --frozen-lockfile
pnpm check
pnpm build
```

本地开发入口是两个常驻进程，请在两个 PowerShell 窗口分别运行：

```powershell
# 窗口 1
pnpm dev:api
```

```powershell
# 窗口 2
pnpm dev:web
```

- API 健康检查：`http://127.0.0.1:8787/health`
- H5：`http://127.0.0.1:4173/`
- 小程序：用微信开发者工具导入 `apps/miniprogram`。
- 不要把真实凭据、原始素材、签名 URL 或聊天记录写进仓库、截图或日志。
- 只需重新生成对内演示包时，运行 `powershell -ExecutionPolicy Bypass -File .\scripts\create-product-demo-package.ps1`；它默认只在 `D:\tmp\warm-letter-ai-family` 下写入生成物。新电脑没有 D 盘时，显式传入 `-OutputRoot (Join-Path $env:TEMP 'warm-letter-ai-family-delivery')`。

## 5. 建议的推进顺序

1. **真实 AI 证据（P0）**：在受控、已授权的脱敏四素材样例上完成真实供应商请求、结构化输出、段落 `sourceRefs`、超时/重试和事实核对证据。生产模式不得回退到 Fake AI。
2. **微信双设备（P0）**：使用正式 AppID 与 HTTPS API，录制上传、另一设备读信/播放/回复、寄信端回查和失效凭据失败路径。H5 截图不能代替此证据。
3. **发布基础设施（P0）**：确定持久化、对象存储、正式审核、删除链路、共享限流、可观测性与部署边界，再评估 G2 用户测试。
4. **内容输出与测试（P1）**：实现同一确认版本的长图/短片，完成授权台账；随后执行年轻用户和长辈测试，记录问题并复测关闭。
5. **比赛材料（P1）**：只在上述证据完成后冻结录屏、PDF、AIGC 声明、平台账号和报名材料。

每完成一项，在阶段报告中记录“完成事实、证据链接、未完成项、风险变化、下一步前三项”；没有可复核证据，不改变门禁状态。
