# 家书生成性能与等待体验说明

最后更新：2026-09-18（Asia/Shanghai）

## 结论

家书生成不是小程序本地卡死，而是服务端异步任务在等待真实 Qwen 多模态链路：语音转写、草稿生成和事实复核都可能产生网络等待。此前客户端最多等待 180 秒，超时后还会误进编辑页并再次等待，用户看起来像“卡住”或重复生成。

本轮已把问题拆成两部分处理：缩短可控制的处理时间，以及让不可避免的远端等待可被理解、可离开、可恢复。

## 已实现

### 客户端

- 相机照片在上传前通过 `wx.compressImage` 缩放到最长边 1600、质量 78；截图保留更高质量并缩放到最长边 2048。压缩失败会回退原文件，服务端仍执行 MIME、魔数和大小校验。
- 多张图片的压缩并行执行，减少串行等待和上传体积。
- 生成页显示阶段、已等待秒数和非终态进度：准备素材、理解图片/语音、整理家书、仍需一点时间。
- 等待 90 秒后可回首页；任务编号和幂等键仍保存在本机，后台任务不会被重复提交。
- 达到客户端轮询上限时，页面显示“已转到后台整理”，不再跳进编辑页触发第二次 180 秒等待。首页“最近家书”里的“生成中”记录可再次打开恢复。

### API 与模型调用

- 同一批媒体先并行读取，再做总字节数校验，避免逐个读取对象。
- Qwen 草稿与事实复核请求增加按篇幅限制的 `max_tokens`：短笺 720、标准 1050、长信 1500，避免 JSON 已完成后继续生成无用内容。
- 事实复核仍保留第二次多模态调用；不能为了追求表面速度而删除事实来源审校。

## 延迟边界

2026-09-16 的公网合成探针（文字、图片、WAV，Qwen 双模型）约 97.5 秒。该数字是一次探针，不是 SLA；用户图片尺寸、录音长度、供应商排队、网络和重试都会改变结果。当前代码改动只在仓库和待部署构建中，公网 API 仍需从已审核分支重新部署，小程序也需重新上传体验版后才会生效。

## 当前推荐配置

对 Qwen 体验环境，服务端环境文件可在完成密钥轮换和费用审核后采用：

```env
OPENAI_COMPATIBLE_TIMEOUT_MS=60000
OPENAI_COMPATIBLE_MAX_RETRIES=1
```

`MAX_RETRIES=1` 仍允许一次 SDK 级瞬时失败重试，但把最坏等待从两次重试降下来。不要在没有监控和回滚的情况下把它设为 0；也不要把超时简单调得很小来制造“更快失败”。当前服务器环境仍可能是 `2`，需要接手人登录服务器后确认并按变更流程修改。

## 部署顺序

1. 在 Node `22.23.2`、pnpm `11.19.0` 下运行 `pnpm check` 和 `pnpm build`。
2. 将审核后的 `master` 部署到香港 API，重启 `warm-letter-api.service`，检查 `/health` 仍为 `demo + WeChat + Qwen profile-match`。
3. 用合成素材完成一次生成任务，记录总耗时、模型错误码和费用；不得把密钥或原始素材写入日志。
4. 在微信开发者工具重新上传小程序，选为体验版，再用任意获授权图片、文字和录音复测：上传、生成、超时离开、首页恢复、编辑确认。

## 后续可选优化

这些项目没有在本轮直接开启，因为会改变安全或供应商边界：

- 用服务端事件推送/长轮询报告真实任务阶段，替代客户端估算进度。
- 为经过授权的媒体做短期对象读取缓存，减少事实复核时的重复读取；缓存必须绑定用户和任务并设置过期清理。
- 评估供应商更快模型或异步批处理，但必须重新完成图片、音频、JSON、来源引用和隐私探针。
- 生产化接入持久化任务队列、共享状态和对象存储；当前单进程内存仓库重启会丢失任务和家书，不能当作生产方案。
