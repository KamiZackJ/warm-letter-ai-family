# 暖笺队内演示手册

目标：在 10 分钟内让队友看懂产品价值、当前已完成能力、第二部分真实内容成果和下一阶段缺口。

## 演示前准备

- 现场第一屏打开受控 CASE-001 团队包根目录的 `index.html`；它把队友提供的裁切照片、原始 m4a、A/B/C 审核稿与本项目的写信工作台放在一起，负责让观看者亲手走完素材、版本比较、归因、确认、阅读与回复。
- 固定使用专用演示账号和受控素材，不展示真实微信聊天、手机号、地址或未授权人物信息。
- 所有测试/构建临时目录使用 `D:\tmp\warm-letter-ai-family`。
- 讲解时明确：代码演示默认是 Fake AI/本地内存数据；真实 AI 和生产部署尚未放行。
- 第二部分原始照片和语音留在受控微信目录，不复制到 Git 仓库。

## A. 受控融合产品展示（约 5 分钟）

在受控 CASE-001 包的 `index.html` 中按顺序操作：

1. 先看物理裁切的货架图，说明只保留货架、商品和价签；播放队友提供的原始 m4a。
2. 保持照片和语音被选中，点击“载入 3 个固定审核版本”，比较 A/B/C；明确三版来自队友固定审核稿，不调用实时 OpenAI。
3. 修改第一段或第二段文字，指出它立即变成“修改后待核对依据”，确认按钮被锁定。
4. 点击“依据语音重新核对”，说明修改不能沿用旧的来源归因。
5. 点击“确认内容，寄出家书”，在收信端展示同一裁切照片、原始音频、字号、来源和回复。
6. 展开“融合依据”抽屉，说明哪些是队友内容成果、哪些由小程序/API/H5 的工程规则承接。

推荐讲法：

> 我们不是把队友材料作为附件放在网页旁边，而是让真实裁切照片、原始语音和审核稿进入一条可操作状态：素材被主动选择，固定稿逐段保留依据，改写后必须重新核对，确认后才进入家人的阅读端。

明确说明：页面是 CASE-001 的本地受控互动演示，三版为固定审核稿；没有调用实时 OpenAI、没有创建真实分享链接，也不能替代微信双真机或生产部署证据。

## B. 内容成果证据（约 2 分钟，仅按需打开）

优先在受控包的 `PROJECT_INTEGRATION.md`、`manifest.json` 和 `evidence/` 中追溯。它们已经随主展示 ZIP 提供，不需要切换到另一份页面。

展示顺序：

1. 查看 `manifest.json`：确认裁切矩形、衍生图哈希和语音哈希；原图不在包内。
2. 查看 `evidence/case-001-output.json`：确认 A/B/C、事实映射和安全结论。
3. 查看 `evidence/privacy-review.json` 和 `evidence/automated-acceptance-tests.json`：说明路人不识别、不描述，T01-T07 为自动预检而非真人评分。
4. 需要快速汇报图时，打开 `exports/warm-letter-case-001-recommended-a.png`；它和推荐 A 正文、裁切图及披露语均由旁边 manifest 核验。
5. 只有评审需要原始工作簿、DOCX、真人测试工具或完整原成果时，才在授权范围内打开原成果包。

推荐讲法：

> 暖笺不是把一句话改写得更煽情，而是把照片、语音和日常碎片接入可核对的家书；不确定的地方主动收敛，不能识别的人不进入正文。

## C. API 闭环展示（约 1 分钟，需要技术下钻时）

在仓库根目录执行：

```powershell
$env:TEMP='D:\tmp\warm-letter-ai-family'
$env:TMP='D:\tmp\warm-letter-ai-family'
pnpm --filter @warm-letter/api demo
```

重点指出输出中的：

- 用户主动注册的素材 ID；
- 生成段落的 `sourceRefs`；
- 用户确认时间先于发布；
- 有期限的 reader link；
- 家人回复被接收。

这一步证明的是后端业务闭环和安全边界，不证明真实 OpenAI 供应商调用。

## D. H5 收信端展示（约 1 分钟，需要技术下钻时）

启动：

```powershell
$env:TEMP='D:\tmp\warm-letter-ai-family'
$env:TMP='D:\tmp\warm-letter-ai-family'
pnpm dev:api
```

需要展示队友 CASE-001 真实受控材料时，在第二个窗口启动。根目录的 `pnpm dev:web` 会自动优先发现 D:\tmp 中的受控包；要显式指定目录时使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\start-controlled-case-reader.ps1 `
  -MediaDirectory 'D:\tmp\warm-letter-ai-family\暖笺_CASE-001_受控团队成果包_2026-08-28\media'
```

打开 `http://127.0.0.1:4173/`，展示：

1. 大字/特大字阅读；
2. 段落来源展开和归因标签；
3. 图片、原始音频和系统朗读的区别；
4. 媒体失败后的重试状态；
5. 回复发送和同页面刷新后的回复保留。

## E. 小程序创作端展示（约 1 分钟，需要技术下钻时）

这一段是仓库内的合成开发链路，默认使用 `synthetic-cooking-demo.png` 和 `synthetic-voice-demo.wav`，不属于队友 CASE-001 真实成果，也不能作为真实素材取证。队友汇报的主展示必须回到 A 段受控成果包；若没有得到小程序端真实媒体适配授权，不要把合成素材截图放进汇报或参赛视频。

使用微信开发者工具导入：

`apps/miniprogram`

展示：素材选择 -> 收信人/语气设置 -> 生成等待 -> 草稿编辑 -> 来源核对 -> 确认 -> Reader。

重点说明改写段落后的四态归因：

- 原始 AI 整理：`ai`；
- 需要重新核对：`needs-review`；
- 已重新核对来源：`sources-confirmed`；
- 用户本人补充：`user-supplied`。

## 演示结束时必须说清楚

- 已完成：队友 CASE-001 真实材料受控接入的本地可运行闭环、公开访问安全、内容安全规则、推荐 A 长图与可移机的团队展示包。
- 未完成：真实 OpenAI 四素材证据、微信双真机、任意确认稿的长图/短片自动生成、真人用户测试和生产部署。
- 下一步：真实 AI/双设备取证、通用确认稿长图导出、真人测试。

## 演示失败时的备用路径

- API 启动失败：继续使用受控 CASE-001 包的离线交互页，打开 `PROJECT_INTEGRATION.md` 与 `evidence/` 说明事实边界；不切换回旧合成素材原型。
- H5 启动失败：使用 API `DEMO_EVIDENCE` 输出和已有 H5 浏览器证据，不临时切换到未声明的静态页面。
- 小程序不可用：不把自动化测试截图称为真机证据，改为展示小程序测试结果和待验收项。
