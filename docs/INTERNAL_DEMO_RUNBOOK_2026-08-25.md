# 暖笺队内演示手册

目标：在 10 分钟内让队友看懂产品价值、当前已完成能力、第二部分真实内容成果和下一阶段缺口。

## 演示前准备

- 固定使用专用演示账号和受控素材，不展示真实微信聊天、手机号、地址或未授权人物信息。
- 所有测试/构建临时目录使用 `D:\tmp\warm-letter-ai-family`。
- 讲解时明确：代码演示默认是 Fake AI/本地内存数据；真实 AI 和生产部署尚未放行。
- 第二部分原始照片和语音留在受控微信目录，不复制到 Git 仓库。

## A. 内容成果展示（约 3 分钟）

打开第二部分成果包中的：

`展示/暖笺_真实素材家书展示.html`

展示顺序：

1. 先看照片：说明系统只提取货架、商品和 9.9 元价签，不识别右侧路人。
2. 播放原始语音：说明不清晰词被降级为“饮品”，没有猜测具体名称。
3. 切换 A/B/C 三版家书：说明三版共享同一事实边界，只改变篇幅和留白。
4. 展示逐句事实映射和安全结论：`safety.status = PASS`。
5. 说明 T01-T07 是自动预检，不是真人用户反馈。

推荐讲法：

> 暖笺不是把一句话改写得更煽情，而是把照片、语音和日常碎片整理成可核对的家书；不确定的地方主动收敛，不能识别的人不进入正文。

## B. API 闭环展示（约 2 分钟）

在仓库根目录执行：

```powershell
$env:TEMP='D:\tmp\warm-letter-ai-family'
$env:TMP='D:\tmp\warm-letter-ai-family'
pnpm --filter @warm-letter/api demo
```

重点指出输出中的：

- 用户主动注册的素材 ID；
- 生成段落的 `sourceRefs`；
- 用户确认时间先于发布；
- 有期限的 reader link；
- 家人回复被接收。

这一步证明的是后端业务闭环和安全边界，不证明真实 OpenAI 供应商调用。

## C. H5 收信端展示（约 3 分钟）

启动：

```powershell
$env:TEMP='D:\tmp\warm-letter-ai-family'
$env:TMP='D:\tmp\warm-letter-ai-family'
pnpm dev:api
pnpm dev:web
```

打开 `http://127.0.0.1:4173/`，展示：

1. 大字/特大字阅读；
2. 段落来源展开和归因标签；
3. 图片、原始音频和系统朗读的区别；
4. 媒体失败后的重试状态；
5. 回复发送和同页面刷新后的回复保留。

## D. 小程序创作端展示（约 2 分钟）

使用微信开发者工具导入：

`apps/miniprogram`

展示：素材选择 -> 收信人/语气设置 -> 生成等待 -> 草稿编辑 -> 来源核对 -> 确认 -> Reader。

重点说明改写段落后的四态归因：

- 原始 AI 整理：`ai`；
- 需要重新核对：`needs-review`；
- 已重新核对来源：`sources-confirmed`；
- 用户本人补充：`user-supplied`。

## 演示结束时必须说清楚

- 已完成：本地可运行闭环、公开访问安全、内容安全规则和真实素材内容成果。
- 未完成：真实 OpenAI 四素材证据、微信双真机、署名确认快照、长图/短片、真人用户测试和生产部署。
- 下一步：固定案例接入、真实 AI/双设备取证、同一确认版本长图导出。

## 演示失败时的备用路径

- API 启动失败：直接打开离线真实素材展示页，并展示 `docs/PHASE_DELIVERY_REPORT_2026-08-25.md`。
- H5 启动失败：使用 API `DEMO_EVIDENCE` 输出和已有 H5 浏览器证据，不临时切换到未声明的静态页面。
- 小程序不可用：不把自动化测试截图称为真机证据，改为展示小程序测试结果和待验收项。
