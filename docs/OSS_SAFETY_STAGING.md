# 微信媒体审核临时副本：生产接入方案

更新日期：2026-09-27。

本文件是代码与运维方案，**不是生产启用记录**。同一合成 PNG、MP3 在香港私有 OSS 的微信检查返回 `failed/-1008`，在北京私有 OSS 收到经过认证的 `pass` 回调，支持进一步验证北京临时副本方案。不能把两份合成素材通过等同于所有用户素材、好友分享或生产切换已验收。用户已明确批准生产按量费用、真实用户素材短时审核副本及仅专用桶审核前缀读写删除的 RAM 服务身份。实际配置与启用进度由 [分享修复记录](./SHARE_REPAIR_2026-09-27.md) 维护。

## 数据范围与访问路径

- 香港 API、SQLite 和原始素材主存储保持原位置。北京 OSS 仅保存需要交给微信检测的临时副本，不迁移家书正文、回复、登录会话或整个素材库。
- 只复制通过本服务类型/大小校验、规范化后的实际素材；送审字节必须与拟分享字节一致。副本不能取代规范化、所有权检查或最终微信审核。
- 使用专用北京 Bucket，标准存储、本地冗余、私有、阻止公共访问。可在确认测试对象已删除后复用暖笺专用北京测试空桶；不复用其他项目的 Bucket。
- 对象前缀统一为 `wechat-safety/`。对象名使用服务端生成的不可预测随机标识，不包含用户姓名、OpenID、手机号、家书正文或原始文件名。
- 用 Bucket 默认 HTTPS 域名签发 GET 预签名 URL，最长 2,700 秒（45 分钟），仅交给微信审核服务器。URL 不进入小程序、Web 页面、分享卡片、正常日志或仓库，不绑定自定义域名，不开启公开读或传输加速。
- 仍以已验签的最终微信回调为准。上传成功、签名成功、提交受理或 OSS 下载成功均不能直接标记素材 `pass`；失败继续保留草稿并阻止寄出。

## 服务端配置约定

| 配置项 | 生产值或约束 |
| --- | --- |
| `WECHAT_MEDIA_STORAGE` | `api` 或 `oss`，默认 `api`；显式设为 `oss` 才启用暂存。当前不得仅因代码合入就改生产值 |
| `WECHAT_OSS_BUCKET` | 经用户批准的暖笺专用北京私有桶 |
| `WECHAT_OSS_REGION` | `oss-cn-beijing`；当前实现只接受本次实测通过的地域，不自动尝试其他地域 |
| `WECHAT_OSS_ACCESS_KEY_ID` | 受限服务端配置中的专用身份凭据，应用 server 直接读取，不进入一般 runtime 配置对象 |
| `WECHAT_OSS_ACCESS_KEY_SECRET` | 同上，禁止返回客户端、打印、提交仓库或写入 journal |
| 对象前缀 | 固定 `wechat-safety/`，不由请求传入 |
| SDK 单次请求 | 最长 10 秒，必须支持真正取消 |
| 完整 `prepare` | 最长 30 秒，包含所有阶段 |
| 单轮 `sweep` | 最长 10 秒，并限制条数和并发 |
| GET 签名有效期 | 最长 2,700 秒（45 分钟） |
| 清理 journal | `UPLOAD_DIR/.wechat-safety-staging`，必须纳入备份与恢复 |

`oss` 模式下缺失、空白或不合法配置应阻止该模式启用，不能静默退回未经验证的路径。`api` 模式不应因出现未使用的 OSS 环境变量而创建临时副本。应用运行身份不具有修改 Bucket 生命周期或其他管理配置的权限。

## 受限应用权限模板

以下是专用 RAM 身份的权限模板，替换 `WARM_LETTER_SAFETY_BUCKET` 后再审查。模板没有账号 ID、AccessKey 或真实凭据，仅授权指定桶中 `wechat-safety/` 前缀内的对象读、写、删。

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "oss:PutObject",
        "oss:GetObject",
        "oss:DeleteObject"
      ],
      "Resource": [
        "acs:oss:*:*:WARM_LETTER_SAFETY_BUCKET/wechat-safety/*"
      ],
      "Condition": {
        "Bool": {
          "acs:SecureTransport": "true"
        }
      }
    }
  ]
}
```

这个身份不应同时继承 `AliyunOSSFullAccess`、其他桶权限、组内广泛权限或桶管理权限；RAM 授权是累加关系，仅增加上面的窄权限不能撤销已有权限。不要使用主账号密钥。生产凭据仅进入受限服务端配置，不写入前端、Git、命令参数或可见日志。

应用明确配置 `cn-beijing` 和目标桶，不依赖列举桶、列举对象或探测其他地域。单文件使用受限的单次 PUT；不为未使用的分片上传、ACL 修改、Bucket 创建/删除、策略修改或生命周期配置授予权限。检查 SDK 是否在初始化时额外调用未获授权的管理接口，必要时调整初始化方式，不扩大到 `oss:*`。

适配器不发送 `x-oss-object-acl`，新对象继承桶权限，避免依赖未授予的对象 ACL 修改权限。**生产开关开启前，运维身份必须实际验证专用桶 ACL 为 private、阻止公共访问已开启、版本控制关闭，且不存在授予匿名读取的 Bucket Policy。** 未完成核验不得启用；应用身份不会自行调用桶管理 API 来补做这项核验。每次 PUT 使用 `x-oss-forbid-overwrite: true`、服务端校验的 Content-MD5，并在同一 10 秒总预算内 HEAD 核对长度、类型和 ETag。默认 GET 签名是本地运算，不进行账号探测或 STS 刷新。

SDK 固定使用 `ali-oss 6.23.0`（lockfile），传输由独立 HTTPS agent 承担，`retryMax: 0`。`urllib 2.44.1` 的 `URLLIB_ENABLE_PROXY` 环境变量会覆盖 SDK 的 `enableProxy: false`，因此适配器发现任何非空值（包括 `0`）就拒绝操作；不要在该服务环境设置此变量。生产不要启用 `DEBUG=ali-oss*`、`DEBUG=urllib*` 或包含这些命名空间的全量调试日志，以免 SDK 自身日志打印认证头、对象路径或签名材料。应用正常错误仅返回固定分类，不附带原始 SDK 错误。

## 新增运行时依赖的部署要求

本次新增 `ali-oss` 及其传递依赖。现有仅替换 `apps/api/dist`、`packages/contracts/dist` 的发布脚本不再足够：服务启动时即加载适配器模块，即使 `WECHAT_MEDIA_STORAGE=api`，缺失依赖仍会导致启动失败。

Linux systemd 的地址族白名单必须包含 `AF_NETLINK`：SDK 的 `address` 依赖在加载时调用 Node/libuv 的 `os.networkInterfaces()`，需要查询本机接口。保持 `AF_INET AF_INET6 AF_UNIX` 并仅增加该项，不授予 `CAP_NET_ADMIN` 或 `CAP_NET_RAW`，保留空的 `CapabilityBoundingSet`、`AmbientCapabilities` 与其他沙箱设置。新安装单元已包含此项；已有安装可使用 [专用 drop-in](../deploy/ubuntu/40-oss-network-introspection.conf)。候选启动验证必须复刻这些安全限制，单独 `import` 或只有 `PrivateNetwork` 的检查不足以验证正式环境兼容。

部署前后比较 `ExecStart` 时只核对可执行文件和参数，结合 unit/drop-in 文件哈希及静态 systemd 属性；不要比较含启动时间和 PID 的完整输出，这些字段每次重启都会变化。

应在独立 **Linux** 候选目录按已审阅提交与 lockfile 安装完整运行时依赖（使用既定 Node 22.23.2／pnpm 11.19.0，`--frozen-lockfile --prod --ignore-scripts` 并限定 API 及 contracts 工作区），加入经核验的 API/contracts 编译产物。不要复制 Windows `node_modules`，不要只复制一个 `ali-oss` 文件夹，也不要在仍运行的生产目录内重装整棵依赖。Linux 候选的 `node_modules/.pnpm`、API 的依赖链接和 contracts 工作区链接必须一起保留并可解析。

在停止旧进程前，以服务身份从候选目录离线 import `ali-oss` 与 `apps/api/dist/oss-safety-media.js`，确认所有依赖可加载；只 import 不构造服务、不加载真实凭据、不请求 OSS。候选应先完成编译、类型检查和回归。取得一致备份后，再切换完整的 API 运行目录（代码和依赖作为同一版本），保留旧运行目录用于回退；若维持原目录布局，必须同时备份和替换相应依赖树，不能只回退 dist。

数据库、上传目录、清理 journal、私密环境文件和 Caddy 配置保持原位置；单独的 OSS 生产开关及凭据仅在获批后启用。部署完成需核对 HTTPS health、SQLite 原记录、回调路径及备份/恢复脚本。此次部署还应同步 `safety-journal-backup.mjs` 与更新后的备份脚本，避免新 journal 没有进入备份。依赖构建或导入失败时维持旧进程服务，不先停机再等待安装。

## 生命周期兜底

由运维身份配置以下规则；应用运行身份不需要生命周期管理权限。若桶中已有规则，应保留并合并，不能覆盖其他规则。

```xml
<LifecycleConfiguration>
  <Rule>
    <ID>warm-letter-wechat-safety-expire-1d</ID>
    <Prefix>wechat-safety/</Prefix>
    <Status>Enabled</Status>
    <Expiration>
      <Days>1</Days>
    </Expiration>
  </Rule>
</LifecycleConfiguration>
```

保持版本控制关闭；否则只创建删除标记可能保留旧版本，需要另行设计版本清理。标准存储没有低频/归档的最低保存时长及 64 KB 最小计量限制。

一天生命周期是失联后的兜底，不是精确的 24 小时删除承诺。OSS 按服务规则调度过期删除；正常流程仍应主动删除并持久重试。该规则只匹配 `wechat-safety/`，不得使用空前缀删除整个桶。

## 租约、超时与删除设计

此设计采用 `UPLOAD_DIR/.wechat-safety-staging` 下的磁盘 journal，不要求数据库结构迁移。journal 只保存受限删除所需的随机对象键、不可逆的素材版本标识、状态、时间及有限错误分类，不保存签名 URL、密钥、用户正文或媒体字节。目录和文件限制为服务身份可读写；拒绝路径穿越、意外符号链接及不属于本项目的对象键。

1. 分配不可变对象键，在任何远程 PUT 前先写租约、`fsync` 文件，并将目录元数据可靠落盘；登记失败就不上传。
2. 租约初始状态表达“可能存在远程对象”。PUT 成功、失败、超时或结果未知都不能直接删除租约；服务重启后能据此清理可能已经上传的对象。
3. 整个 `prepare` 最长 30 秒，覆盖读取、上传、签名和状态持久化。`signedGetUrl` 接受可选 `AbortSignal`；SDK 网络请求必须真正响应取消，不能仅用 `Promise.race` 让调用方超时后在后台继续上传或签名。
4. 返回签名前复核取消、租约和素材版本。若素材已被覆盖、删除、账号注销或操作已超时，禁止继续送审；任何已上传副本进入清理队列。内容版本改变后不能复用旧审核结果。
5. 保留副本直到最终回调或审核等待截止，随后主动删除。清理任务每轮最长 10 秒，限制本轮条数及并发，单个失败不能阻塞全部条目；删除失败保留 journal，下轮继续，禁止无限紧密重试。
6. 只有远程删除已确认成功，或受限请求明确确认对象不存在，才清除对应租约。权限错误、网络超时、未知状态及日志写失败不等于删除成功。
7. journal 应随 `UPLOAD_DIR` 一起备份。需核查现有“只复制数据库引用文件”的备份工具是否遗漏隐藏 journal 目录，不能仅因路径在 `UPLOAD_DIR` 下就声称已备份。恢复时先复核删除记录并恢复清理，再开放正常写入；不要恢复或重新上传已删除素材。

并发 `prepare` 与清理必须协调：不能在 PUT 尚可能成功时先删远程对象并移除租约，导致迟到 PUT 重新产生无记录副本。进程内合并不能代替重启后的持久状态；单进程假设应明确保持。

签名有效期和对象删除是两种不同控制。若远程 DELETE 失败，已签发链接可能在剩余签名期内继续被持有者读取，最长为签发后的 45 分钟；不能宣称删除请求后所有审核 URL 立即失效。过期 URL 不能再使用，但副本本身仍须删除，不能因签名过期就丢弃租约。不得为清理失败的副本自动续签或延长访问期。

## 费用与使用限制

北京标准本地冗余存储目录价为 **0.12 元/GB/月**；官网同时列有中国内地标准本地冗余 **0.09 元/GB/月** 的官网折扣，预估保守使用目录价。北京外网流出流量在 00:00–08:00 为 **0.25 元/GB**、08:00–24:00 为 **0.50 元/GB**；内/外网上传流量本身免费。标准 PUT 请求当前每月每地域前 500 万次免费，GET 前 2,000 万次免费，超出部分均为 **0.01 元/万次**。地域总用量及其他应用消耗会影响免费余额，不能仅凭暖笺请求量保证免费。

例如，不考虑免费额度，以 1,000 个 1 MiB 副本、每份存一小时并被微信完整下载一次估算，下行约 0.9766 GB，忙时下行约 0.49 元；额外下载或重试会按实际流量增加费用。该示例不是保证值或费用硬上限，长期使用还应核对香港主机既有流量套餐的出站用量。

OSS 默认按量付费，资源包用完后超出部分仍按量计费。费用预算和预警**不会限制实际资源使用**，账单通常延迟约 3–4 小时，不足 0.01 元的费用会累计后出账。因此，不能把“设置 1 元预算”、免费档、购买存储包或关闭自动续费描述为“绝不会自动产生额外费用”。

应用可以限制文件大小、每天暂存字节、任务并发、重试次数、签名时长和积压租约数量；达到限制时拒绝新送审并保留草稿。这些属于应用使用控制，不能作为阿里云账单金额的严格硬封顶承诺。本次用户已单独明确批准生产按量计费和受限访问，区别于此前仅合成素材的测试授权；授权不等于已启用，实际状态见分享修复记录。

## 必须覆盖的失败回归

| 失败点 | 必须保持的结果 |
| --- | --- |
| journal 创建、写入、`fsync` 或目录落盘失败 | 不发生 PUT，不签 URL，不提交微信 |
| PUT 已成功，但客户端超时或连接断开 | 留下可恢复租约；不把不确定结果当作无对象 |
| 登记后崩溃、PUT 后崩溃、签名后崩溃 | 重启后的有界清理可处理租约，不生成未经核验的分享 |
| SDK 延迟返回或忽略取消 | 30 秒后不产生新的签名/送审；迟到对象仍有持久清理记录 |
| PUT 与 sweep 重叠 | 不出现先删除租约、后成功 PUT 的永久孤儿对象 |
| DELETE 超时、403、5xx 或响应不合法 | 租约仍保留；10 秒 sweep 有界退出；不宣称远程已删 |
| 素材删除、替换、账号注销与上传并发 | 旧版本不再送审或寄出；临时副本进入清理 |
| 最终回调通过/拒绝/下载失败、重复及迟到回调 | 保留现有 fail-closed 和版本绑定；新旧任务不互相放行 |
| 小于、等于、超过大小限制；实际类型与 MIME 不符 | 不超预算；拒绝非法文件；送审字节与分享字节一致 |
| URL、对象键、Bucket、前缀、过期时间或 HTTP 方法异常 | 不能访问其他桶/前缀，不签超 45 分钟或非 HTTPS URL |
| 凭据缺失、配置一半、地域与 Endpoint 不匹配 | 启动校验或调用明确失败；不得退化为公开读、HTTP 或跳过审核 |
| 备份/恢复遗漏 journal，租约损坏或磁盘满 | 可见失败并拒绝不受控上传；不能静默丢失删除责任 |
| 错误包含签名 URL、OSS 凭据、用户内容 | 正常日志及响应只出现有限安全错误分类 |
| 任意云故障或费用用量限制到达 | 家书保留草稿，给出可恢复提示；不制造分享凭据 |
