## 问题

小程序 AppID `wx281b5275e4a1601f` 调用 `media_check_async`（version 2、scene 4）。照片与 MP3 均被受理并返回 trace ID，但认证后的异步回调均返回 `errcode: -1008`。应用依此阻止素材家书分享。

素材地址位于 `https://api.warmjiashu.xyz`，使用 45 分钟有效期的独立签名，不依赖登录 Cookie、不跳转。照片为 JPEG、174,649 字节；录音为 MP3、36,045 字节。相同文件可由自有公网客户端正常 GET，HTTP 200、MIME、长度与文件头正确。

## 已验证

- DNSPod 和阿里公共 DNS 都返回目标服务器 IPv4；无 AAAA 记录。
- 微信加密消息回调可抵达服务器并完成认证，应用返回 HTTP 200；HTTP 200 是回调接收成功，不代表素材审核通过。
- API 使用可信 RSA 2048 位证书。TLS 1.2 客户端限制为 `ECDHE-RSA-AES128-GCM-SHA256`，有 SNI、无 SNI 均通过证书链与域名校验；未关闭证书验证或启用 TLS 1.0/1.1。
- 实际发送的链为 `api.warmjiashu.xyz → YR2 → Root YR（ISRG Root X1 交叉签名）`，OpenSSL 带域名验证到 ISRG Root X1，返回 `0 (ok)`。三张证书签名均为 `sha256WithRSAEncryption`，符合 [Let's Encrypt 默认链](https://letsencrypt.org/certificates/)。并非仅止于 Root YR 的短链。
- 2026-09-23 14:12:26–14:13:26 UTC（北京时间 22:12:26–22:13:26）做过一次有界双向 TCP 443 诊断。303 包、104,404 字节，60 秒完整结束，未触及上限。
- 同时段 12 条相同特征连接带正确 API SNI、声明 TLS 1.2 与 ECDHE-RSA/ECDSA 支持。记录到服务器 ServerHello、选择 `0xc02f` 及后续客户端 RST；没有可确认的明文 TLS Alert，应用没有收到审核素材 HTTP 请求。首轮未分析更早的 FIN，不能由 RST 次序认定客户端收到证书后拒绝。
- 该轮两条失败回调的时间为 14:13:23.951 和 14:13:25.722 UTC，均为 `-1008`。

时间相关性不能单独证明上述每条连接来自微信，现有证据也不足以确定具体证书或网络原因。此前补充 SNI 默认值和切换 RSA 证书都未解决下载失败。

## 完整抓取复核与结论修正

- 15:11:58.759–15:12:58.827 UTC（北京时间 23:11:58.759–23:12:58.827）完整抓取 350 包、148,524 字节，28 条连接均双向；抓取长度 65,535 字节，无截断，未触及 2 MB 上限。
- 12 条声明 56 个密码套件的连接，发送 269 字节 ClientHello 后 0.012–0.185 毫秒即发出 FIN，均早于服务器首个 TLS 数据（ClientHello 后 2.416–3.078 毫秒）。FIN 是客户端提前关闭发送方向，后续 RST 不能证明客户端收到证书后拒绝它。不能据此确认这些连接就是微信媒体下载器，或断言丢包、中间设备故障。
- 完整 ServerKeyExchange 为 `rsa_pkcs1_sha512`、`secp256r1`，公钥 65 字节、签名 256 字节，均在客户端声明支持范围内。另 8 条声明 50 个密码套件的连接采用相同签名、曲线及完整三张证书链，其中 4 条进入双方 ChangeCipherSpec 阶段。原来因抓取截断而未知的签名/曲线已经补齐，未发现可支持 PSS 不兼容推断的证据。
- 本轮确认操作的客户端返回时间为 15:12:25.852 UTC；两条审核记录在 15:12:34.312 和 15:12:36.877 UTC 更新为 `failed/-1008`。15:12:34.311、15:12:36.875 和 15:12:40.540 UTC 收到认证回调并返回 200，包含重复回调；所有 HTTP 方法的审核素材请求仍为 0。
